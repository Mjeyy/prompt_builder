# Prompt Builder

Утилита для сборки промптов по ремонту и тюнингу автомобилей. Два способа запуска:

- **Терминал** — интерактивное меню, готовый промпт копируется в буфер обмена macOS. Текст промпта в терминал **не выводится**.
- **Визуальный интерфейс** — то же для сборки промпта (с превью) плюс режим проверки markdown-таблиц: поле `summary` должно содержать ровно 4 абзаца, разделённых `<br><br>`.

## Что делает утилита

1. Загружает список автомобилей из `autos.md`.
2. Загружает шаблоны промптов из `repair_prompts.md` (ремонт) и `tuning_prompts.md` (тюнинг).
3. Предлагает выбрать авто, категорию и раздел.
4. Подставляет в шаблон значения `make`, `model`, `generation`, `engine` вместо плейсхолдеров `[MAKE]`, `[MODEL]`, `[GENERATION]`, `[ENGINE]`.
5. Копирует готовый промпт в буфер обмена через `pbcopy`.
6. В визуальной версии — открывает локальные MD-таблицы, находит ошибки в `summary` и позволяет исправить их по очереди.

## Требования

- macOS (для копирования в буфер обмена используется `pbcopy`)
- Python 3.10 или новее
- Git (для клонирования репозитория)

## Установка на macOS

### 1. Проверить, установлен ли Python

```bash
python3 --version
```

Ожидаемый результат, например:

```text
Python 3.11.9
```

Версия должна быть **3.10 или выше**.

### 2. Установить Python, если его нет

Рекомендуется [Homebrew](https://brew.sh/). Если Homebrew ещё не установлен:

```bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
```

Установка Python:

```bash
brew install python@3.11
```

Проверка:

```bash
python3 --version
```

### 3. Проверить Git

```bash
git --version
```

Если Git не установлен:

```bash
xcode-select --install
```

или через Homebrew:

```bash
brew install git
```

### 4. Создать директорию и клонировать репозиторий

```bash
mkdir -p ~/Projects
cd ~/Projects
git clone <URL-ВАШЕГО-РЕПОЗИТОРИЯ> prompt_builder
cd prompt_builder
```

Если проект уже скачан — просто перейдите в его папку:

```bash
cd /путь/к/prompt_builder
```

### 5. Создать виртуальное окружение

```bash
python3 -m venv .venv
```

Активировать окружение:

```bash
source .venv/bin/activate
```

После активации в начале строки терминала появится `(.venv)`.

### 6. Установить зависимости

```bash
pip install --upgrade pip
pip install -e .
```

Установка в режиме `-e` (editable) позволяет сразу видеть изменения в коде без переустановки.

### 7. Запустить утилиту

Терминал:

```bash
python -m prompt_builder
```

или, если окружение активировано:

```bash
prompt-builder
```

Визуальный интерфейс:

```bash
python -m prompt_builder.gui
```

или:

```bash
prompt-builder-gui
```

### 8. Завершение работы

**Терминал**

- В меню выберите **Выход**
- Или нажмите `Ctrl+C`

**Визуальный интерфейс** — закройте окно.

Чтобы выйти из виртуального окружения: `deactivate`

## Как работать с утилитой

Раздел ниже — про **терминальный** режим. Визуальный интерфейс описан отдельно.

После запуска терминала откроется интерактивное меню (стрелки ↑↓ и Enter).

### Шаг 1 — Выбор авто

Список строится из `autos.md`. Формат строки:

```text
Chevrolet Tahoe · GMT K2XX · L86
```

### Шаг 2 — Категория

- **Ремонт** — промпты из `repair_prompts.md`
- **Тюнинг** — промпты из `tuning_prompts.md`

### Шаг 3 — Раздел

Один из девяти разделов, например:

```text
ENGINE — Двигатель и топливная система
BRAKES — Тормозная система
```

### Результат

В терминале появится отчёт:

```text
✓ Промпт скопирован в буфер обмена

  Авто:       Chevrolet Tahoe · GMT K2XX · L86
  Категория:  Ремонт
  Раздел:     ENGINE — Двигатель и топливная система
```

Далее вставьте промпт в нейросеть: `Cmd+V`.

### Меню после копирования

| Действие | Что происходит |
|----------|----------------|
| **Повторить** | Снова копирует тот же промпт в буфер |
| **Другой раздел** | Выбор другого раздела для того же авто и категории |
| **Другая категория** | Переключение Ремонт ↔ Тюнинг для того же авто |
| **Сменить авто** | Возврат к выбору автомобиля |
| **Выход** | Завершение программы |

## Визуальный интерфейс

Запуск: `python -m prompt_builder.gui` или `prompt-builder-gui`.

На главном экране два режима.

### Сборка промпта

Тот же сценарий, что в терминале, на одном экране:

1. Найдите и выберите авто (есть поиск).
2. Выберите категорию: **Ремонт** или **Тюнинг**.
3. Выберите раздел.
4. Проверьте превью и нажмите **Скопировать в буфер**. Пока кнопка не нажата, буфер обмена не меняется.

Чтобы собрать другой промпт, просто выберите другое авто, категорию или раздел — превью обновится сразу.

### Проверка таблиц

Режим есть только в визуальной версии. Нужен локальный `.md` с markdown-таблицей и колонкой `summary` (образцы лежат в `docs/`).

Правило ошибки: в ячейке `summary` должно быть **ровно 4 абзаца**, разделённых `<br><br>`. Меньше или больше — ошибка.

Как работать:

1. **Открыть файл** — выбираете MD-таблицу. Сканирование читает **исходный файл** и не меняет его.
2. На экране — **общее число ошибок**.
3. **Режим редактирования** создаёт в той же папке копию `имя_fix.md` (например `Tank_300.md` → `Tank_300_fix.md`) и открывает ошибки по очереди: номер строки, название статьи (`topic_title`), текст `summary`.
4. В редакторе абзацы разделяются пустой строкой. Можно стирать, дополнять и переписывать текст.
5. **Сохранить и далее** пишет правку в копию `*_fix.md` и открывает следующую ошибку. Если абзацев всё ещё не 4, переход не выполняется. Исходный файл остаётся без изменений.
6. Когда очередь закончилась, появится уведомление. Нажмите **Повторить сканирование** — проверяется уже копия. Цель — **0 ошибок**. Если снова найдены — повторите правки в том же `*_fix.md`.

## Как обновлять данные

Все данные хранятся в markdown-файлах в корне проекта. Код менять не нужно — достаточно отредактировать файлы и перезапустить утилиту.

### Таблица автомобилей (`autos.md`)

Файл — markdown-таблица с колонками:

| make | model | generation | engine |
|------|-------|------------|--------|
| Chevrolet | Tahoe | GMT K2XX | L86 |

**Добавить новое авто** — добавьте строку в конец таблицы:

```markdown
| Toyota | Camry | XV70 | 2AR-FE |
```

**Изменить существующее** — отредактируйте нужную строку.

Правила:

- Первая строка — заголовки колонок.
- Вторая строка — разделитель `|---|---|...`.
- Далее — строки с данными.
- Не удаляйте и не переименовывайте колонки `make`, `model`, `generation`, `engine`.

### Промпты ремонта (`repair_prompts.md`)

Каждый раздел оформлен так:

```markdown
### 1. ENGINE — Двигатель и топливная система (Repair)

```text
текст промпта с плейсхолдерами [MAKE], [MODEL], [GENERATION], [ENGINE]
```
```

**Добавить новый раздел:**

1. Скопируйте существующий блок.
2. Измените номер, ID (латиница, например `BRAKES`), русское название.
3. Обновите текст внутри блока ` ```text `.
4. Сохраните суффикс `(Repair)` в заголовке.

**Изменить промпт** — редактируйте только текст внутри ` ```text ... ``` `. Сами плейсхолдеры `[MAKE]`, `[MODEL]`, `[GENERATION]`, `[ENGINE]` не удаляйте — приложение подставит в них данные авто.

### Промпты тюнинга (`tuning_prompts.md`)

Формат заголовка:

```markdown
## 1. ENGINE — Двигатель и топливная система

```text
текст промпта
```
```

Правила те же, что для ремонта, но заголовок начинается с `##` и **без** `(Repair)`.

### После изменений

1. Сохраните файл.
2. Перезапустите утилиту (`python -m prompt_builder`).
3. Проверьте, что новые данные появились в меню.

При ошибке в формате файла программа выведет сообщение с описанием проблемы и завершится.

## Частые проблемы

**`Команда pbcopy не найдена`** — утилита рассчитана на macOS. На Linux/Windows копирование в буфер не поддерживается.

**`Ошибка загрузки данных`** — проверьте формат `autos.md` или файлов промптов (заголовки, блоки ` ```text `).

**Меню не отображается корректно** — запускайте в обычном терминале (Terminal.app, iTerm, встроенный терминал IDE), не в неинтерактивном режиме.

**После `git clone` нет `.venv`** — виртуальное окружение создаётся вручную (см. раздел «Установка»), в репозиторий оно не входит.
