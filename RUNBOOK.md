# Ранбук: Prompt Builder

Пошаговая инструкция: установка, запуск, ежедневная работа и разбор типичных поломок на macOS.

Краткое описание проекта — в [README.md](README.md).

---

## 1. Что это за приложение

Два независимых запуска:

| Режим | Команда | Для чего |
|-------|---------|----------|
| Терминал | `python -m prompt_builder` | Собрать промпт и сразу скопировать в буфер. Текст промпта в терминал не печатается. |
| Окно | `python -m prompt_builder.gui` | Сборка промпта с превью, гороскоп **и** проверка MD-таблиц (поле `summary`). |

Ремонт, тюнинг и гороскоп есть и в терминале, и в окне. Проверка таблиц — только в окне.

---

## 2. Требования

- macOS (буфер обмена — `pbcopy`)
- Python **3.10+**
- Для окна обязателен **Tk** (`tkinter` / модуль `_tkinter`)
- Git — только если клонируете репозиторий

Проверка Python:

```bash
python3 --version
```

Проверка Tk **тем же** интерпретатором, из которого будете делать `.venv`:

```bash
python3 -c "import tkinter; print('tk', tkinter.TkVersion)"
```

Если видите `No module named '_tkinter'` — этот Python для GUI не подходит. Что делать: раздел [5.3](#53-nomodule-_tkinter--окно-не-запускается).

## 3. Установка с нуля

Выполняйте команды **по одной**, из папки проекта.

### 3.1. Перейти в проект

```bash
cd /путь/к/prompt_builder-master
```

### 3.2. Выбрать Python с Tk

На этой машине надёжный вариант — установщик python.org:

```bash
/usr/local/bin/python3.11 -c "import tkinter; print('ok', tkinter.TkVersion)"
```

Если команда печатает `ok 8.6` (или другую версию Tk) — используйте именно этот интерпретатор для venv.

Homebrew `python3` (часто 3.12 / 3.13 / 3.14) **часто собран без Tk**. Им можно пользоваться только для терминала, либо после `brew install python-tk@…`.

### 3.3. Создать виртуальное окружение

Если старый `.venv` есть и он «чужой» или битый — удалите его:

```bash
rm -rf .venv
```

Создание (подставьте свой рабочий Python):

```bash
/usr/local/bin/python3.11 -m venv .venv
source .venv/bin/activate
```

В приглашении должно появиться `(.venv)`. После активации `python` — это уже интерпретатор из `.venv`, не системный.

Проверка:

```bash
which python
python --version
python -c "import tkinter; print('tk ok')"
```

`which python` должен указывать **внутрь** `.venv/bin/python`, а не в `/opt/homebrew/bin/python3`.

### 3.4. Поставить зависимости

Всегда через модуль, не голым `pip` (иначе zsh может взять Homebrew `pip` со сломанным shebang):

```bash
python -m pip install --upgrade pip
python -m pip install -e .
```

Ожидаемые пакеты: `prompt-builder`, `questionary`, `customtkinter`.

### 3.5. Запуск

Терминал:

```bash
python -m prompt_builder
```

Окно:

```bash
python -m prompt_builder.gui
```

После активации `.venv` те же команды: `prompt-builder` и `prompt-builder-gui`.

### 3.6. Остановка

- Терминал: пункт **Выход** или `Ctrl+C`
- Окно: закрыть окно, в терминале при необходимости `Ctrl+C`
- Выйти из venv: `deactivate`

## 4. Ежедневная работа

Каждый раз:

```bash
cd /путь/к/prompt_builder-master
source .venv/bin/activate
```

Дальше — нужный режим.

### 4.1. Терминал: сборка промпта

1. Выберите авто (стрелки, Enter).
2. Категория: **Ремонт**, **Тюнинг**, **Гороскоп: описание авто** или **Гороскоп: прогноз**.
3. Для ремонта и тюнинга — раздел (ENGINE, BRAKES, …).
4. Для прогноза — дата начала (сегодня и ближайшие 13 дней или ввод `ГГГГ-ММ-ДД`) и число дней: **7** (по умолчанию), **10**, **30** или вручную.
5. Промпт сразу копируется в буфер. В терминале только отчёт (авто, категория, для ремонта/тюнинга раздел, для прогноза дата и дни).
6. Вставьте в нейросеть: `Cmd+V`.
7. Дальше: **Повторить** / **Другой раздел** (только ремонт и тюнинг) / **Другая категория** / **Сменить авто** / **Выход**.

Данные: `autos.md`, `repair_prompts.md`, `tuning_prompts.md`, `horoscop_auto.md`, `horoscop_date.md`. После правок этих файлов перезапустите программу.

### 4.2. Окно: сборка промпта

1. `python -m prompt_builder.gui`
2. **Сборка промпта**
3. Найдите авто, выберите категорию и раздел.
4. Превью обновляется сразу. **В буфер ничего не копируется**, пока не нажмёте **Скопировать в буфер**.
5. Другое авто / категория / раздел — просто кликните другой пункт в списках.

### 4.3. Окно: гороскоп

1. `python -m prompt_builder.gui`
2. **Гороскоп: описание** или **Гороскоп: прогноз**
3. Найдите авто. В промпт уходят только марка и модель.
4. Для прогноза выберите день в календаре (старт включительно) и число дней: **7** / **10** / **30** / **Вручную**.
5. Превью обновляется сразу. **В буфер ничего не копируется**, пока не нажмёте **Скопировать в буфер**.

### 4.4. Окно: проверка таблиц (summary)

Нужен локальный `.md` с markdown-таблицей и колонкой `summary`. Образцы: папка `docs/`.

Правило ошибки: в `summary` должно быть **ровно 4 абзаца**, разделённых `<br><br>`. Меньше или больше — ошибка.

Порядок:

1. **Открыть файл** — сканируется **исходник**, он не перезаписывается.
2. Смотрите число ошибок.
3. **Режим редактирования** создаёт рядом копию `имя_fix.md`  
   (`Tank_300.md` → `Tank_300_fix.md`).
4. Ошибки идут по очереди: строка файла, статья (`topic_title`), текст `summary`.
5. В редакторе абзацы делите **пустой строкой** (это и есть `<br><br>` в файле).
6. **Сохранить и далее** пишет в `*_fix.md`. Если абзацев не 4 — переход запрещён.
7. Когда очередь кончилась — **Повторить сканирование** (проверяется уже копия). Цель: **0 ошибок**.

Исходный файл остаётся как был. Итог работы — файл `*_fix.md`.

## 5. Проблемы и решения

Ниже — сбои, которые уже встречались на этой машине, и похожие.

### 5.1. `zsh: command not found: python`

**Симптом.** `python -m prompt_builder.gui` не находится.

**Почему.** На macOS часто есть только `python3`. Команда `python` появляется после `source .venv/bin/activate`, если venv живой.

**Что делать.**

```bash
source .venv/bin/activate
which python
python -m prompt_builder.gui
```

Без venv: `python3 -m …`, но зависимости тогда должны быть установлены в этот `python3`. Надёжнее всегда работать из `.venv`.

---

### 5.2. Битый `.venv` и `pip: bad interpreter`

**Симптом.**

```text
zsh: /opt/homebrew/bin/pip: bad interpreter: /opt/homebrew/opt/python@3.11/bin/python3.11: no such file or directory
```

или `.venv/bin/python` — битая ссылка.

**Почему.** Окружение собрали под другой путь/пользователя или под Homebrew Python, который потом удалили. `source .venv/bin/activate` «включается», но `python` внутри мёртв. zsh берёт системный `/opt/homebrew/bin/pip`.

**Что делать.** Не чинить старый venv. Пересоздать на **живом** Python с Tk:

```bash
deactivate
rm -rf .venv
/usr/local/bin/python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e .
```

Правило: ставить пакеты только так: `python -m pip …`, не `pip …`.

Проверка, что pip из venv:

```bash
which python
python -m pip -V
```

Путь должен содержать `.venv`.

---

### 5.3. `No module named '_tkinter'` — окно не запускается

**Симптом.** После `python -m prompt_builder.gui`:

```text
ModuleNotFoundError: No module named '_tkinter'
```

Терминальный режим при этом может работать.

**Почему.** CustomTkinter сидит на Tk. Homebrew Python 3.12/3.13/3.14 часто **без** Tcl/Tk. venv наследует это.

**Что делать — вариант A (предпочтительный).** Venv на python.org 3.11 (у него Tk уже есть):

```bash
deactivate
rm -rf .venv
/usr/local/bin/python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
python -c "import tkinter; print('tk ok')"
python -m prompt_builder.gui
```

**Что делать — вариант B.** Остаться на Homebrew Python 3.14:

```bash
brew install python-tk@3.14
python -c "import tkinter; print('tk ok')"
python -m prompt_builder.gui
```

Формула должна совпадать с версией Python в venv (`python-tk@3.12`, `@3.13`, `@3.14`).

Проверка «этот python умеет окно»:

```bash
python -c "import tkinter; print(tkinter.TkVersion)"
```

---

### 5.4. Кнопки в окне не нажимаются (нужно сворачивать окно)

**Симптом.** Окно открылось, клики по кнопкам игнорируются. Иногда помогает свернуть/развернуть, иногда только с десятой попытки. Может казаться, что «всё зависло».

**Почему.**

1. Процесс запущен из Terminal, это не `.app`. Tk на macOS иногда рисует окно, но не делает его активным — клики не доходят.
2. CustomTkinter рисует фон рамки холстом. Холст может перекрыть кнопку.
3. Кнопка CTk срабатывает на отпускание мыши и только если курсор уже «вошёл» в кнопку. Пока окно не в фокусе, вход не регистрируется.
4. Опасно: принудительно делать окно «поверх всех» (`-topmost`) и дергать его через `osascript`. Тогда окно видно, но клики пропадают ещё сильнее.

В коде это закрыто в `prompt_builder/gui/clickfix.py` (клик по кнопке, холст рамки уводится назад, без topmost).

**Что делать пользователю.**

1. Полностью закрыть GUI: закрыть окно и `Ctrl+C` в терминале.
2. Запустить снова из активированного venv: `python -m prompt_builder.gui`.
3. Один раз кликнуть **заголовок окна** (серая полоса сверху), затем кнопку.
4. Не запускать вторую копию GUI параллельно.
5. Если курсор над кнопкой не меняется на «палец» — окно всё ещё не принимает мышь; клик по заголовку, затем кнопка.

Если после обновления кода поведение то же — убедитесь, что запущен именно этот проект (editable-установка `pip install -e .`) и процесс один.

### 5.5. `Ошибка загрузки данных`

**Симптом.** При старте терминала, сборки промпта или гороскопа в GUI — сообщение про `autos.md` или файлы промптов.

**Почему.** Сломана markdown-таблица, заголовок раздела или пустой файл гороскопа.

**Что делать.**

- `autos.md`: первая строка с `make | model | generation | engine`, вторая — `|---|`, дальше строки данных.
- Ремонт: заголовок `### N. ID — Название (Repair)` и блок ` ```text `.
- Тюнинг: `## N. ID — Название` без `(Repair)` и блок ` ```text `.
- Гороскоп: `horoscop_auto.md` и `horoscop_date.md` в корне, не пустые.
- Запускайте из **корня проекта**, где лежат эти файлы.

---

### 5.6. `Команда pbcopy не найдена`

Только macOS. На Linux/Windows копирование в буфер этим приложением не поддерживается.

---

### 5.7. Меню терминала «ломается» / нет стрелок

Запускайте в Terminal.app, iTerm или встроенном терминале IDE. Не в неинтерактивном пайпе (`python -m prompt_builder | cat`).

---

### 5.8. Правки попали не в тот файл / оригинал изменился

**Как задумано.** Скан читает исходник. Правки пишутся только в `*_fix.md` после входа в режим редактирования.

**Если правите уже `имя_fix.md`.** Вторая приставка `_fix` не добавляется — работа идёт в этом файле.

**Если в папке уже был старый `*_fix.md`.** При первом входе в правку в новой сессии (открыли **оригинал**) копия перезаписывается свежей копией оригинала.

Не открывайте GUI двумя окнами на один и тот же файл.

---

### 5.9. В GUI промпт «не копируется сам»

Это не баг. Превью обновляется при выборе. В буфер — только кнопка **Скопировать в буфер**. В терминале копирование по-прежнему сразу после выбора раздела.

---

### 5.10. После `git clone` нет `.venv`

Окружение в git не входит. Создайте по разделу [3](#3-установка-с-нуля).

---

### 5.11. `prompt-builder` / `prompt-builder-gui` не найдены

Пакет не установлен в текущий интерпретатор или venv не активирован.

```bash
source .venv/bin/activate
python -m pip install -e .
python -m prompt_builder
python -m prompt_builder.gui
```

Команды `python -m …` не зависят от PATH-скриптов и предпочтительнее.

## 6. Чеклист «GUI не стартует»

Пройдите сверху вниз.

1. `source .venv/bin/activate` — есть `(.venv)`?
2. `which python` — путь внутри `.venv`?
3. `python --version` — 3.10+?
4. `python -c "import tkinter"` — без ошибки?
5. `python -c "import customtkinter, questionary"` — без ошибки?
6. Каталог — корень репозитория (`autos.md` на месте)?
7. `python -m prompt_builder.gui`

Если пункт 2 или 4 провален — не ставьте пакеты поверх, а **пересоздайте venv** (разделы 5.2 и 5.3).
